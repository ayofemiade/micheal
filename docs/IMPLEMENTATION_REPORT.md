## 2. How the hero works

- **Server-rendered first frame.** CSS container units lay the photographs out at the exact 1:1 camera, so the first paint is the finished composition. This was verified with JavaScript disabled, and the result is pixel-identical to the JS frame.
- **One camera, two transforms.** `scene.ts` computes the camera: log-scale zoom, with panning anchored by interpolating the visible width. `PullBackMotion` applies one transform to the photographs and one to the drawing. Nothing else moves.
- **Resolution.** A high-resolution face crop (an exact crop of the print, generated by the image script) covers 1:1 and fades out as the full print becomes sharp enough.
- **Composition by shape.** Wide stages get the side-by-side composition. Phones *and portrait tablets* get the stacked one, with a white veil keeping copy legible over the shirt.
- **Accessibility.**
  - All four chapters are in the DOM in reading order.
  - Focusing a control in a hidden chapter moves the camera there instantly (verified: visible within 60 ms).
  - The ruler is a `nav` with `aria-current`.
  - Reduced motion makes the camera *cut* between distances.

## 4. Measured results

Lighthouse 12.8.2 run through Edge against the production build (`next start`), local machine. "Mobile" is Lighthouse's default throttled profile (slow 4G, 4× CPU).

| Run | Performance | Accessibility | Best practices | SEO | LCP | TBT | CLS |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| Mobile, first build | 54 | 100 | 100 | – | 5.6 s | 1,180 ms | 0 |
| Mobile, final (2 runs) | **81–82** | **100** | **100** | 92–100 | 3.7–3.9 s | 310–320 ms | **0** |
| Desktop, final | **99** | **100** | **100** | **100** | **0.9 s** | 30 ms | **0** |

Final page weight is 565 KB, including 196 KB of JavaScript, 80 KB of fonts and AVIF images.

**What changed the numbers:**
1. **Removed Motion for React.** Its only use was the mobile menu, and its 42 KB chunk was 87% unused, so the menu now animates with CSS.
2. **GSAP loads after the browser is idle.**
3. **The mobile LCP image (the full print) gets `fetchPriority="high"`.**
4. **Tried and reverted:** not preloading the body font. There was no LCP gain, and first paint got worse (1.0 s → 1.2–1.3 s).

**Honest reading of mobile LCP.** The observed LCP phases on this machine add up to about 270 ms (TTFB 21 ms, load delay 25 ms, load 24 ms, render delay 204 ms). The 3.7–3.9 s figure is Lighthouse's *simulated* slow-4G estimate, and it is above the 2.5 s target. The remaining cost is mostly the framework's baseline JavaScript. **This needs real-device and field measurement before anyone calls it passed or failed.**

## 6. Deviations from the approved plan

- **Motion for React is no longer used.** It was removed for performance (§4); the dependency is still in `package.json` and can be uninstalled.
- **No font subsetting.** The font licence forbids modifying the files, so the planned subsetting step was dropped. 80 KB for two variable families is within budget.
- **Orientation decides the hero composition,** not only screen width. Found at 768×1024.
- **Unconfirmed MAO frames are excluded.** The drum frame from the prototype was replaced, because it is signed "Michael Adebiyi Photography".
